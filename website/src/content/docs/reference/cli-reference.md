All yRest functionality is accessible through the `yrest` CLI. Run `yrest --help` or `yrest <command> --help` for inline documentation.

```bash
yrest <command> [options]
```

## yrest serve

Start the mock server from a YAML file.

```bash
yrest serve db.yml [options]
yrest serve db.yml --port 4000 --watch --delay 200
```

### Flags

| Flag            | Short | Type              | Default     | Description                                         |
| --------------- | ----- | ----------------- | ----------- | --------------------------------------------------- |
| `--port`        | `-p`  | `number`          | `3070`      | Port to listen on                                   |
| `--host`        | `-h`  | `string`          | `localhost` | Host to bind                                        |
| `--base`        | `-b`  | `string`          | —           | URL prefix for all routes (e.g. `/api/v1`)          |
| `--watch`       | `-w`  | `boolean`         | `false`     | Reload database on file changes                     |
| `--readonly`    | `-r`  | `boolean`         | `false`     | Reject all write operations (POST/PUT/PATCH/DELETE) |
| `--delay`       | `-d`  | `number`          | `0`         | Add simulated latency in ms to every response       |
| `--snapshot`    | `-s`  | `boolean`         | `false`     | Enable `/_snapshot` save/reset endpoints            |
| `--pageable`    | —     | `number?`         | —           | Wrap list responses in `{ data, pagination }`       |
| `--id-strategy` | —     | `increment\|uuid` | `increment` | Strategy for auto-assigning `id` on POST            |

## yrest init

Scaffold a new `db.yml` and optional `yrest.config.yml` in the current directory.

```bash
yrest init
yrest init --sample relational
yrest init --sample ecommerce
```

### Flags

| Flag       | Type                           | Description                        |
| ---------- | ------------------------------ | ---------------------------------- |
| `--sample` | `basic\|relational\|ecommerce` | Template to use (default: `basic`) |
| `--config` | `boolean`                      | Also create `yrest.config.yml`     |

## yrest handler

Scaffold a handler function stub in `yrest.handlers.js`.

```bash
yrest handler login
yrest handler login --method POST --path /login
yrest handler login --method POST --path /login --register
```

### Flags

| Flag         | Type      | Description                              |
| ------------ | --------- | ---------------------------------------- |
| `--method`   | `string`  | HTTP method hint (adds JSDoc comment)    |
| `--path`     | `string`  | Path hint (adds JSDoc comment)           |
| `--register` | `boolean` | Also add the `_routes` entry to `db.yml` |

## yrest types

Generate TypeScript interfaces from a YAML database: one interface per collection, a `CollectionName` union and a `Collections` map.

```bash
yrest types db.yml                               # prints to stdout
yrest types db.yml --output db.types.ts          # writes a file
yrest types db.yml --output db.types.ts --watch  # regenerates on every change
```

### Flags

| Flag       | Short | Type      | Default  | Description                                                      |
| ---------- | ----- | --------- | -------- | ---------------------------------------------------------------- |
| `--output` | `-o`  | `string`  | (stdout) | Write to a file instead of printing to stdout                    |
| `--watch`  | `-w`  | `boolean` | `false`  | Regenerate on every change of the source file (needs `--output`) |

### Output

```ts
// Auto-generated by yrest types — do not edit manually.
// Source: db.yml

/** Item of the `users` collection. */
export interface User {
  id: number;
  name: string;
  email?: string;
}

/** Item of the `posts` collection. */
export interface Post {
  id: number;
  title: string;
  /** FK → users.id */
  userId: number;
}

/** Union of all collection names in the source file. */
export type CollectionName = "users" | "posts";

/** Maps each collection name to its item array type. */
export interface Collections {
  users: User[];
  posts: Post[];
}
```

### Type rules

- **Names** — collection name in singular PascalCase: `users` → `User`, `post_tags` → `PostTag`, `categories` → `Category`. On a collision the plural form is kept.
- **Optionality** — inferred from every item: present on all items → required, missing on any → optional.
- **Unions** — different types across items become a union; `null` adds `| null`. Nested objects are merged into one shape and array elements are pooled.
- **`_schema` wins** — `_type`, `_required` (and the `required` / `optional` shorthand), `_enum`, `_nullable` and `_items` override the inference. `_description`, `_format` and `_deprecated` become JSDoc. Fields declared only in `_schema` are included.
- **Relations** — `many2one` / `one2one` foreign keys from `_rel` get a `FK → target.id` comment.

:::note
`yrest types` only reads the file. `__uuid_gen` / `__fk` directives are not resolved and `db.yml` is never rewritten.
:::
